## Canonical Boundary

Phase 0.1 canonical content is data-first and portable.

- Canonical content in Strapi:
  - `studio-page`: routing, status, block order by canonical block key, shell/theme refs, SEO, conversion, CTA, taxonomy
  - `studio-block`: canonical key, family/type, schema-valid imported DOM snapshot data (`domJson`, `classMap`, `stylesheetRef`), theme/fidelity metadata
  - `studio-theme`: token set, `themeScopeClass`, `themeMode`, token coverage, theme debt
  - `studio-setting`: first-class studio fidelity settings
- Derived preview:
  - page and block previews are generated by the site renderer from canonical Strapi state at request time
  - public runtime and studio preview must rebuild from canonical state, not persisted preview documents
- Disposable artifacts:
  - `previewHtml`, `publishedPreviewHtml`, `sourcePreviewHtml`, and `targetPreviewHtml` are non-canonical cache fields only while legacy compatibility remains
  - these fields must be fully regenerable and must never be treated as source-of-truth content
  - save/publish paths must not persist host-bound runtime artifacts such as `localhost`, `_next/static`, or injected runtime scripts
